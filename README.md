# Segue

**Your chart, your set, your cue.** Segue is a native macOS app for a performing musician: get songs in as clean ChordPro charts (paste, type or import), build setlists with per-show key and capo, and play the gig from a dark stage view that fits the whole song on one screen at a size you can read from a stand. The library is plain `.cho` files you own, with a rebuildable search index that understands romanized Hindi spellings. It is local-first: no account and no backend; analytics and crash reports are opt-in.

## Requirements

- A Mac with **Apple silicon** (the app is arm64 only).
- **macOS 26** or later.
- **Xcode 27.1** (Swift 6.4), the release toolchain, with its **Metal Toolchain** component (MLX compiles Metal kernels; `make bootstrap` installs it with `xcodebuild -downloadComponent MetalToolchain`).
- **[mise](https://mise.jdx.dev)**. Every other tool (Tuist, SwiftLint, SwiftFormat, Node, pnpm, uv, actionlint, ShellCheck, jq, yq) is pinned in [`.mise.toml`](.mise.toml) and run through `mise exec`; nothing is installed globally.

## Quick start

```sh
mise install            # pinned tools
make bootstrap          # tools, git hooks, Swift packages, generates Segue.xcworkspace
make quick              # inner loop: lint, Personal build, package tests (no long ones)
make e2e-one TEST=SegueLiveE2ETests        # one XCUITest class (or Class/testName)
make e2e-smoke          # the E2E smoke set: library to editor to setlist to live
make gate               # workstream gate: package tests, App Store build, smoke set plus the
                        # E2E classes mapped from what changed since origin/main
make check              # release gate, everything: regenerate, lint, generated-file checks, site,
                        # builds, all tests, the full XCUITest suite and the App Store purity check
```

Every target has a one-line `##` description in the [Makefile](Makefile). After editing `Project.swift` or a package manifest, `make generate` (`make check` does it first). The Xcode project is generated by Tuist and git-ignored.

## Two flavours

| | App Store | Personal |
|---|---|---|
| Scheme | `Segue-AppStore` | `Segue-Personal` |
| Bundle ID | `dev.ryandsilva.segue` | `dev.ryandsilva.segue.personal` |
| Ships | Mac App Store | Ryan's Mac only |
| Extra modules | none | `Packages/SeguePersonalModules` |

Personal-only features (planned: synced-lyrics lookup, import from URL) depend on models or sources whose licences or terms do not allow store distribution. They live in their own package, compiled in only under the `SEGUE_PERSONAL` condition, so the App Store build never contains their source or their symbols. `make verify-appstore` proves it on every `make check`: it builds the App Store flavour and fails if anything personal reaches its build graph, link map, binary or bundle.

design/                   colour tokens and icon geometry (sources for make tokens / make icon)

Generated files (colour tokens, icon layers, the changelog pages, sitemap and redirects) are never edited by hand: change the source and run `make tokens`, `make icon` or `make site`. `make check` fails when they are stale.

## Testing

Integration first: the core suite runs against a real file-system library, the real parser and a real GRDB index on fresh temporary state, and the XCUITest suite drives the real app on a freshly seeded library. Unit tests are kept for tricky pure logic (parsing, music theory, layout maths).

Runs are tiered by cost:

1. After each change: `make quick`, plus `make e2e-one TEST=Class[/test]` for the UI you touched.
2. At the end of an assignment (workstream gate): `make gate`, the smoke set plus the E2E classes mapped from the changed paths (`UITests/e2e-map.tsv`).
3. Before a release and at the end of each phase: one full `make check`, the release gate.
4. Before pushing: `make repo-check`, the same Linux checks CI runs, offline once tools are fetched.

CI is deliberately light ([.github/workflows](.github/workflows)): SwiftLint and SwiftFormat, the colour-token and HTML checks for the site, docs checks and actionlint, all on Linux runners. Builds and tests run locally only.
