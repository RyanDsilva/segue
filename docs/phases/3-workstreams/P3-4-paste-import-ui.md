## Session rules (apply to every P3 workstream)

- `cat` is aliased to eza and can hang: use `command cat` or the Read tool. Never `rm -rf`: use `trash`. Never an em dash in any file: use "-".
- Sibling workstreams edit the same working tree concurrently: expect unrelated diffs, never revert or "fix" files you do not own, and stage only your own files.
- Commits: local only, signed (`git commit -S`), conventional messages, no co-author lines, one commit per resolved step. If signing fails with "failed to fill whole buffer", 1Password is locked: leave the staging intact, tell the orchestrator, never commit unsigned. Never push.
- Test budget (R113): per step only targeted in-process suites (`swift test --filter <Suite>`); new UI behaviour gets in-process SegueUI tests, and a new XCUITest only for a flow that cannot be tested in-process. At the end of the workstream ONE `make quick` plus ONE `make e2e-one` per UI test class you added or changed. NO `make gate` per workstream (the orchestrator runs one per wave), no `make check` (phase gate only, P3-9), no E2E retry loops (a failure is investigated, not re-run), no duplicate builds in scratch worktrees. Real FM/MLX calls never run inside `make check` or `make gate`.
- Stop and ask the orchestrator at any decision fork or spec-vs-code inconsistency.

## Goal

Every way a song comes in (New Song, clipboard, empty state, `⌘V` on the list, Import, drag and drop, `.crd`) lands in one review sheet that shows the deterministic result instantly and streams AI refinements in, with nothing saved before Accept; its metadata block is P3-10's song card; plus the analytics rows that measure it.

## Steps

0. **Design directions (R39 style):** 2-3 renders of the review sheet's AI marking (how AI-decided labels/metadata differ from rule-based conversion, the "Refining with..." line, the R69 footer note) within the chosen layout "a", plus the batch list (R96) and the New Song input state (R83). The metadata block is P3-10's song card in draft mode: do not design a second metadata form. Ryan picks before step 3.
1. **Entry points (R75, R83):** File > New Song (`⌘N`) and every other New Song control open the review sheet in an **input state** ("Paste or type a song"; `⌘V` pastes; the clipboard is never read before that) with a **"Start blank"** link that runs today's new-song path (`LibraryViewModel+Editing.swift`) and opens the editor with the song card focused on Title (P3-10 exposes the focus seam). `MenuShortcuts.newSongFromClipboard` = File > "New Song from Clipboard" `⌥⌘V` (the clash test must pass; also confirm in the running editor that `⌥⌘V` is not taken by the text system, report if it is); "Paste a Song" in the empty-library state; `⌘V` while the song list (not a text field, not the editor) has focus. Keyboard help (`?` overlay) lists the new item automatically via `MenuShortcuts.all`.
2. **Import routing:** `SongFileTypes.importExtensions` gains `crd` (update the comment that says "not accepted in 0.5"); `prepareImport` candidates are classified by `IngestPipeline` (`isAlreadyChordPro` -> direct import as today, A29; others -> review queue). **Several conversion files open ONE review sheet (R96):** a list of every converted file with a checkbox (ticked by default) and a per-file preview and song card; **Import N Songs** commits the ticked ones together (one undoable import); unticked files are listed in the import summary as not imported. AI refinement runs per file in the background (one model load per file, R94) and never blocks the list.
3. **Review sheet** (`Packages/SegueUI/Sources/SegueUI/Paste/`): opens with `IngestResult` immediately; refinement runs through `AIServices` (P3-2) and streams in; the user can edit or Accept at any time (Accept cancels refinement); original left, result right; the metadata block is **P3-10's song card in draft mode** (title, artist, key with the detected key as a suggestion that is written only if picked (R101), tempo, capo, time, proficiency, tags with P3-6's starter suggestions); unknown lines and bad tokens flagged; footer names the provider and shows the R69 note; with the AI toggle off (R93) the footer says so. **During a show (R95) the paste routes are disabled** (menu items disabled with the reason as help text, the empty-state button disabled, `⌘V` on the list does nothing and shows the reason); the exact scope is open question 26, which blocks this sub-step until Ryan rules (recommendation a: every route into the review sheet, New Song goes straight to Start blank, already-ChordPro imports stay allowed). Accept -> `commitImport`; Cancel -> nothing written. Undo of an accepted paste follows WS2a's Undo Import.
4. **Download link (R93):** a quiet one-line link to Settings > AI in the review sheet footer when the result came from FM or code and the curated model is not installed, and in the Welcome card (step 5). No popup, no tip, no sheet offers the download.
5. **Welcome card + tip:** one card in the Welcome sheet's revisit cards ("Paste any chord sheet": what it does, that it stays on the Mac, a button to Settings > AI) and one TipKit tip on the empty library / song list pointing at `⌥⌘V`. Follow WS2b's TipKit rules (no tips during a show).
6. **Analytics (R74):** new `AnalyticsEvent` rows for `Segue.AI.pasteFinished`, `Segue.AI.modelDownload`, `Segue.AI.assistantUsed` and `Segue.AI.smartFilterUsed` with the enums/buckets in spec section 11 (exact names fixed here; every value <= 24 chars and allowlist-valid): `source` gains `newSong`, `fallback` gains `aiOff` and has no `duringShow`, `outcome` gains `unticked`, and **`romanHindi` (Bool, R98)** is set when the converter's romanized-Hindi detection fired. `IngestBody` allowlist test extended; emit `pasteFinished` here, once per file in a batch (the other emitters belong to P3-3, P3-6, P3-7: they call the cases you define). Correction bucket = edit distance between the AI-proposed labels/metadata and the accepted ones.

## Tests

In-process SegueUI integration tests (real store, parser, temp library, `ScriptedProvider`): each entry point produces the sheet; New Song shows the input state and Start blank creates an empty song; Accept writes exactly the expected `.cho` (no detected key unless picked); Cancel writes nothing; `.crd` and `.txt` go through review, `.cho` does not; a three-file batch with one unticked imports two; the paste routes are disabled during a show. Analytics: the rendered payloads of the new rows pass the allowlist. E2E `SeguePasteE2ETests`: clipboard paste -> sheet -> Accept -> song with correct sections; Cancel leaves the library unchanged; New Song -> paste -> Accept, and New Song -> Start blank; three files -> one sheet -> untick one -> two songs imported. Suites: `PasteReviewTests`, `AnalyticsVocabularyTests`.
